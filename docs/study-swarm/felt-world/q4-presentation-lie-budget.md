A renderer may interpolate, juice, and spatialize only on presentation-owned layers that never write hashed entity state: an explicit lie budget bound to sim events, not a sterile draw-only stage.

1. **GGPO treats audio, video, and non-impacting SFX as non-state, requires stepping the sim without rendering, and shows that a two-frame flash fired inside a rollback is consumed so the remote player never sees it.** Cannon, GGPO Developer Guide (https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md). Implication: defer juice until after commit; hashed state is inputs plus serializable sim. Failure: leaky render in the step loop desyncs or vanishes.

2. **Snapshot interpolation reconstructs a visual approximation from received snapshots without running the simulation on the receiving side; extrapolation of colliding rigid bodies fails because the interpolator does not know floors, springs, or contacts.** Fiedler (2014), Snapshot Interpolation (https://gafferongames.com/post/snapshot_interpolation/). Implication: lerp between two sim-emitted poses is a lie budget; inventing the next pose is a second sim. Stay hashed: the snapshots.

3. **Source interpolates entities 100 ms in the past (`cl_interp 0.1`) so the renderer always has two snapshots; lag compensation must subtract that same interp delay, and turning interp off breaks hit detection.** Valve Developer Community, Source Multiplayer Networking (https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking). Implication: presentation lag is allowed if authority accounts for it; the drawn pose is not the hashed pose. Failure: trusting the drawn pose for hits (client-claimed truth).

4. **Unity Netcode presents predicted objects on a prediction tick and interpolated ghosts on a delayed interpolation tick; PresentationSystemGroup uses unscaled wall-clock time, SimulationSystemGroup uses scaled sim time.** Unity, Time synchronization, Netcode for Entities 6.6.0 (https://docs.unity3d.com/Packages/com.unity.netcode@6.6/manual/time-synchronization.html); System groups, Entities 6.5.0 (https://docs.unity3d.com/Packages/com.unity.entities@6.5/manual/systems-update-order.html). Implication: camera, VFX, and audio live in presentation time; hashed clock is sim tick. Failure: juice that reads sim `DeltaTime` becomes a second clock.

5. **Juice It or Lose It stacks particles, trails, and screen shake on a Breakout clone until it “feels alive,” without changing brick-break rules.** Jonasson and Purho (2012), GDC Europe, Juice It or Lose It (https://gdcvault.com/play/1016789/Juice-It-or-Lose). Implication: shake the camera, not the entity; particles are presentation. Failure: juice that moves hashed positions.

6. **WCAG 2.3.1 forbids more than three flashes per second (or above general/red-flash thresholds); Xbox XAG 117/118 require camera shake, bob, and flash to be independently disableable because vestibular mismatch and photosensitive seizures are presentation hazards, not sim hazards.** W3C Understanding SC 2.3.1 (https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html); Microsoft XAG 117 and 118 (https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117). Implication: the lie budget must be user-killable without changing the hash.

7. **ARINC 661 splits Cockpit Display System (view) from User Application (logic); the graphics kernel does not know the meaning of data, only widget updates. FAA overlay guidance requires inconsistent layers to be obvious or annunciated, and forbids overlays that become a second model.** ARINC 661 overview (https://protoframework.sourceforge.io/articles/article_arinc661.html); FAA HF-STD-001 ch. 3.8 (https://hfcc.dot.gov/publications/docs/GeneralGuidance/zz_FAA_GeneralGuidanceDoc_Chapter_03_Section_08.html). Implication: stage is a CDS: decorate, don’t own. Hash mismatch already maps to “annunciate staleness.”

8. **Diegetic UI that pretends to be world-truth fails as a complete HUD replacement; Far Cry 2 needed fading non-diegetic elements, and Andrews’ rule is functionality preservation over authenticity.** Fagerholt and Lorentzon (2009), Beyond the HUD (http://publications.lib.chalmers.se/records/fulltext/111921.pdf); Andrews (2010), Game UI Discoveries (https://www.gamedeveloper.com/design/game-ui-discoveries-what-players-want). Implication: HUD may lie; diegetic chrome must not invent sim facts the hash does not own.
